# ISLA V2.23 — speed-based building damage

Building ram damage used to stop increasing at 44 × the vehicle's ram multiplier. The cap is removed in both the browser physics and the authoritative multiplayer Worker. Damage still depends on impact speed squared, vehicle mass and any purchased ram upgrade.

For normal cars, with inward impact speed `v` in meters per second:

`damage = v < 15 ? 0 : (v² - 225) × 0.043 × mass × ramFactor`

Remaining building HP is clamped to zero. At the normal 100 HP building limit, excess damage has no extra effect. The existing 15 m/s (54 km/h) threshold stays in place to keep slow pushing harmless. The collision uses speed into the wall, so a fast sideways scrape does not count as a full-speed ram. Beast retains its existing 100-damage hit at 4 m/s and above.

| Direct impact speed | Standard car damage | HP remaining from 100 |
| --- | ---: | ---: |
| 100 km/h | 23.5 | 76.5 |
| 150 km/h | 65.0 | 35.0 |
| 200 km/h | 123.0 | 0 — destroyed |

Car mass and ram upgrades multiply these values. The per-building 0.7-second contact cooldown, collapse effects, server distance/speed checks and permanent first-destruction Aura history are unchanged. Damage is calculated by the server for multiplayer rather than accepting a damage amount from a client.

This patch includes no price, upgrade, weapon, coin, trail or joystick changes. It preserves the complete V2.22 trails and controls follow-up and does not repeat the Cado_Codes test credit. The manifest retains its historical filename but now declares 2.23, and both the menu and health endpoint identify V2.23.

## Validation

New checks cover increasing damage across all 19 cars and all three upgrade levels, actual wall collisions, glancing contact, cooldowns, one-time collapse rewards, multiplayer parity, invalid hit rejection and late-join building HP. The older truck regression now expects sufficiently fast rams to demolish a building.

The world build, Cloudflare Worker dry-run and source checks passed. The full suite ran 220 checks; 219 passed and one older Fern test still expected release 2.22. After updating that assertion to 2.23, all seven tests in that file passed. All three new V2.23 collision/multiplayer tests passed in the full run. No runtime code changed after that run.

The ZIP was checked for corruption, applied to a fresh copy of the latest V2.22 repository, and all 116 source-file hashes verified. Folder preparation succeeded. The patch excludes generated files and deployment configuration. Verification used the actual collision code and a local multiplayer Worker; browser driving was not checked in this run.
